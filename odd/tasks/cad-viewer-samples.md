# cad-viewer sample files

Real third-party sample files for the sandbox, with documented provenance and licenses,
for both 2D drawings and 3D models. Branch `feat/samples` from `main` at v0.3.0 (`4b9b6cb`).

## Specs

- **S1** — "habrá que localizar ficheros de ejemplo, tanto 2D como 3D"
- **S2** — (user answer, verbatim option label) "Buscar archivos reales de terceros" — real
  files from third parties are added to the sandbox, next to the existing synthetic ones.
  "The idea would be to bring real drawings and models from third parties, with documented
  provenance and license."
- **S3** — (user answer, verbatim option label) "CC0 + CC-BY con atribución" — only files
  under CC0 1.0 or CC BY are redistributed; CC BY requires attribution that is visible to the
  user and preserved in the repository. This question's preview states the required artifacts:
  `examples/sandbox/public/samples/SOURCES.md` and a visible credits block on the sandbox
  pages.
- **S4** — Inherited from the foundation: the repository stays MIT; sample assets carry their
  own licenses; every asset is attributed with author, license and source URL.

## Decisions

- **Where the real files live:** `examples/sandbox/samples/` (committed), not
  `public/`, because `public/samples/` is generated by `prepare-assets.mjs`.
- **Single source of truth:** `examples/sandbox/samples/samples.json` holds file, title,
  author, license, source URL and SHA-256. `SOURCES.md` is the human-readable attribution
  file required by CC BY practice; a test fails if the two drift or a file is unlisted.
- **Synthetic fixtures stay** in `packages/*/test/fixtures`: they are deterministic, tiny and
  used by unit tests. Real files are sandbox assets and get their own parse test.
- **License policy for the future:** CC0 1.0 and CC BY only. Anything GPL/CC-BY-SA would need
  its own isolated directory and an explicit decision, as with the DWG plugin.
