# cad-viewer 3D

View-only 3D support: mesh formats first, rendered with three.js in a separate MIT package.
Branch `feat/3d` from `main` at v0.2.0 (`2436655`). Target version: 0.3.0 (additive, new packages).

## Specs

- **S1** — "tenemos que empezar a plantear el soporte para ficheros 3D"
- **S2** — Formats, first wave: "Mallas ligeras: STL + OBJ (Recomendado)" — "Parsers propios, MIT, cero dependencias. Cubre el caso «ver un modelo 3D» con muy poco riesgo y valida toda la cadena (modelo, renderer, visor, wrappers)." Out of scope for this wave: rich materials, scene hierarchy, B-rep.
- **S3** — Renderer: "three.js en paquete aparte (Recomendado)" — `cad-viewer-3d` (MIT) with `three` as a peer dependency. Who only uses 2D must not pay for it. Future kernels stay isolated like the DWG plugin: STEP/IGES via `occt-import-js` (LGPL-2.1) and IFC via `web-ifc` (MPL-2.0), each in its own optional package.
- **S4** — Model and API: "CadScene 3D + Cad3DViewer separados (Recomendado)" — `CadScene`/`CadMesh` live in the MIT core; `Cad3DViewer` and the wrappers live in `cad-viewer-3d`. **`CadDocument`, `Bounds`, `ViewState` and the 2D viewer are not touched**, so there is no 2D regression. Shared conventions: layers, `CadViewerError` codes, locale catalogs, event names.
- **S5** — 0.3.0 scope: "Ver + orbitar + encuadrar + capas + PNG (Recomendado)" — orbit camera, fit, layer visibility, flat shading and wireframe, PNG export. Explicitly **not** in 0.3.0: 3D measurement, section planes, face picking and a parts tree (planned for 0.3.x).
- **S6** — Inherited constraints from the foundation (S7 of `cad-viewer-foundation.md`): core stays MIT with zero runtime dependencies; every non-permissive dependency is an opt-in, separately licensed package; the DWG plugin stays GPL-3.0.
- **S7** — Inherited conventions: the viewer's own texts come from the i18n catalogs (default `es-ES`, fallback `en`), every library error carries a stable `code` + `params` with an English `message`, wrappers are plain TypeScript (no SFC/JSX toolchain), and the sandbox gains a 3D page.

## Design notes

- `CadScene` is deliberately small: `meshes[]` (positions/normals/indices, per-mesh material, layer, name), `layers`, `bounds`, `units`, `unsupported`. No textures, no animation, no scene graph in 0.3.0 — OBJ/STL cannot express them and the parts tree is out of scope (S5).
- Both loaders parse on the main thread first (async signature, like the 2D loaders), so a worker can be added later without API breaks.
- Edges are rendered as a separate line overlay from the same geometry, so CAD models keep readable silhouettes in flat shading without extra data from the format.
- three.js is a **peer** dependency: consumers install it, `cad-viewer-3d` never bundles its own copy, and the 2D packages stay free of it.

## Contracts (T1 output, binding for T2–T7)

- Core (MIT) exports `CadScene`, `CadMesh`, `CadMaterial`, `CadSceneLayer`, `Bounds3` (`packages/core/src/scene/types.ts`), and `createEmptyScene(format)`, `DEFAULT_MATERIAL` (`{ name: "default", color: 0xb4bcc4 }`), `meshBounds(mesh)`, `sceneBounds(meshes)` (`packages/core/src/scene/scene.ts`). `FormatLoader<T = CadDocument>` and `FormatRegistry<T = CadDocument>` are generic, so 3D loaders are `FormatLoader<CadScene>` and the 2D API is unchanged.
- 3D error codes in the core catalog (es-ES/en): `stl-truncated` `{ triangles, bytes }`, `stl-invalid-number` `{ line }`, `obj-invalid-number` `{ line }`, `obj-invalid-index` `{ index, line }` (`index` is the raw token string), `webgl-unavailable` `{}`. Loaders throw `new CadViewerError(code, englishMessage, { params })` where `englishMessage` must equal `formatCadError(error, "en")` (tests assert it); never a bare `Error`.
- **STL (T2)** — `packages/3d/src/loaders/stl.ts` exports `parseStl(bytes: Uint8Array): CadScene` and `stlLoader: FormatLoader<CadScene>` (`id: "stl"`, `extensions: [".stl"]`). Binary when `byteLength >= 84` and `84 + 50 * count <= byteLength` (trailing bytes allowed, even if the header starts with `solid`); otherwise ASCII when the text starts with `solid` (after an optional BOM/whitespace); otherwise `stl-truncated` with the declared `triangles` (0 when the file is shorter than 84 bytes) and the actual `bytes`. Binary: one mesh named after the printable header text up to the first NUL (trimmed, fallback `"solid"`), `metadata.header` holds it. ASCII: one mesh per `solid … endsolid`, named after the rest of the `solid` line (fallback `"solid"`); keywords are case-insensitive; a bad number throws `stl-invalid-number` with its 1-based line; a facet without exactly 3 vertices is skipped and counted in `unsupported` as `"facet"`. Every mesh: layer `"0"` (present in `scene.layers`, visible), material `DEFAULT_MATERIAL.name`, non-indexed `positions` (9 floats per triangle), per-vertex `normals` equal to the facet normal, or the normalized cross product when the facet normal is zero/non-finite, or `(0, 0, 1)` for degenerate triangles. `scene.bounds = sceneBounds(scene.meshes)`, `format: "stl"`. `canLoad` accepts both flavours by the same rules. `load()` throws `abortError()` when `signal` is aborted (before and after parsing) and reports `onProgress({ phase: "parse" })`.
- **OBJ (T3)** — `packages/3d/src/loaders/obj.ts` exports `parseObj(text: string): CadScene` and `objLoader: FormatLoader<CadScene>` (`id: "obj"`, `extensions: [".obj"]`, decodes UTF-8 and strips a BOM). Statements: `v x y z [w]` (extra values such as vertex colors ignored), `vn`, `vt` (ignored), `f` with `v`, `v/vt`, `v//vn`, `v/vt/vn` corners, negative (relative) indices, polygons fan-triangulated; `o name` sets the object, `g name…` sets the group (rest of the line, trimmed), `usemtl name` sets the material; `s` and comments ignored; a trailing `\` continues a line. `mtllib`, `l`, `p`, `curv`, `surf` and any other unknown keyword are counted in `unsupported` by keyword. Meshes are split by (object, group, material) in first-appearance order; mesh `name` = object name, else group name, else `"default"`; `layer` = group name, else `"0"`; every used layer is in `scene.layers` (visible). Each `usemtl` name becomes a `CadMaterial` whose color comes from a fixed 8-color palette in order of first use (`.mtl` files are not resolved in 0.3.0); faces before any `usemtl` use `DEFAULT_MATERIAL`. Normals: the face's `vn` values when every corner has one, else the flat triangle normal. A bad number in `v`/`vn` throws `obj-invalid-number`; a corner index that is not a non-zero integer or is out of range throws `obj-invalid-index` with the raw token and the 1-based line; faces with fewer than 3 corners are skipped and counted as `"f"`. Empty meshes are not emitted. `canLoad` needs a line starting with `v ` followed by a number within the first 4 KiB and no NUL byte there. Same abort/progress rules as STL.
